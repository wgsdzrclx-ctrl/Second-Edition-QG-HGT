本稿记录已审阅的修改方向。2026-11-08已按第一阶段在独立分支编写代码，保留原模型开关，尚未执行测试、模型试跑或训练，等待用户检查；具体改动见[代码修改记录](QC_HGT代码修改记录_20261108.md)。下文是设计与验收要求，不表示新模型已经通过运行验证。第一阶段为四组累计实验，后续增强与正式对比分开安排。

2026-11-09再次按本稿逐项核对，补齐标准化后缺失mask的传递、增强checkpoint恢复配置检查，并补充验收用例和需求对应表，详见代码修改记录步骤9；仍未执行模型或训练。

**建议先解决三个问题：保留幅值、区分变量、利用时序。**

目前存在可以直接验证的输入信息损失。先修复这些问题，能够判断 QC-HGT 的性能是否主要受输入表示限制，再决定如何强化质量与一致性机制。目标是提高 Accuracy 和 Macro-F1，并让增益能通过对照实验解释；具体提升幅度需要训练验证。

| 已确认的现象 | 对模型的影响 | 对应修改方向 |
| --- | --- | --- |
| 恒为10与恒为100的窗口，经当前七维统计量 LayerNorm 后，最大差仅约1.19e-7 | 一些绝对水平变化难以区分 | 用训练集固定标准化保留幅值差异 |
| 交换同单元 XMEAS1、XMEAS2 的完整窗口，诊断探针中模型输出完全不变 | 缺少物理变量身份，可能分不清异常发生位置 | 加变量ID与所属单元ID |
| 分类主干仅读取七个统计量，原始窗口主要用于质量描述 | 局部波动、变化顺序等动态信息利用不足 | 加轻量时序编码器 |
| 十次QC训练均达到30轮上限，最佳轮次在27–30 | 当前预算不足以证明已收敛 | 后续单独验证训练预算，第一轮先固定预算 |

前两个探针用于证明特定表示限制，不等同于真实测试集精度实验，也不保证对应修改必然提分。详细证据见[完整审查报告](QC_HGT提升方案与对比实验_20261104.md)和[诊断结果](../tmp/audit/model_probe_results.json)。

**第一阶段：四组累计实验。**

| 编号 | 实验组 | 本组新增内容 | 主要回答的问题 |
| --- | --- | --- | --- |
| A | 原始 QC-HGT | 保持当前模型 | 当前流程能否复现已保存基线？ |
| B | A＋固定标准化 | 改进数值输入表示 | 保留幅值信息能否提高诊断能力？ |
| C | B＋变量身份 | 加变量与单元嵌入 | 在固定标准化基础上，变量身份是否有增益？ |
| D | C＋时序编码 | 加共享轻量TCN | 在前两项基础上，原始时间序列是否进一步改善诊断？ |

这里的C−B、D−C表示在已有改动基础上的增量收益。四组累计实验不能单独证明各模块在所有组合下均有效；若需要在论文中论证独立贡献，再补“仅变量ID”等独立消融。此前完整审查报告包含更广的候选矩阵，本稿采用上述四组作为首轮执行范围。

**B组具体方向：用训练集固定尺度处理数值。**

当前模型先计算每个变量的均值、标准差、最小值、最大值、趋势、末值、首末差，再对这一七维向量单独做 LayerNorm。建议改为在训练数据上拟合每个变量的均值与标准差，之后固定使用：

`标准化观测 = (原始观测 − 训练均值) / max(训练标准差, epsilon)`

拟合只使用本轮选定训练窗口中的有效观测，按run与时间点去重；不使用验证集、测试集或额外未选训练数据。第一版使用选定训练数据中的全部类别，避免同时增加“正常数据拟合或全类别拟合”的搜索因素。拟合结果随checkpoint保存并记录数据索引指纹。

保持已有退化规则：在原始物理单位上施加噪声、漂移、缺失等退化，再标准化有效观测、重新计算七维统计量。缺失位置单独用mask标识，计算时排除，补充值在标准化后处理，避免把原始补零解释为有效观测。对应的时移负例也使用同一固定尺度。

本组取消原始七维向量的样本内 LayerNorm，其他图传播、分类器和损失设置保持基线方案。质量描述分支仍读取原始单位的观测和mask，以便先隔离诊断表示的影响。质量分支的尺度校准留到后续实验单独验证。

验收重点：相同输入在训练/验证/推理使用完全一致的尺度；验证或测试数据变化不影响拟合参数；常量变量不产生NaN；标准化后的七维输入仍能区分前述10与100窗口。标准化参数应可独立加载，不能只保存在运行内存中。

**C组具体方向：让模型知道每个节点代表什么。**

为41个传感器和11个执行器设置不同的全局变量ID，并增加6个工艺单元的身份嵌入。变量ID只能来自物理变量定义，不能使用故障类别、run编号或样本序号。

第一版采用小型可训练embedding，例如变量ID为16维、单元ID为8维，与B组统计特征拼接后投影到现有64维隐藏空间。所属单元信息由现有映射得到。保留原图结构、池化方式与质量分支，先验证身份编码本身的增量作用。

需要同步修改输入适配接口：当前图对象已有编号，但统一模型接口没有完整传递它们。还需将sensor和actuator原本各自从1开始的编号映射成互不冲突的ID，确认PyG批处理不会改变物理身份。

验收重点：ID在不同batch大小和图顺序下保持一致；交换两个物理变量的观测、但保留各自ID时，模型不再被结构强制输出相同结果。若只是改变节点排列、同时正确重排特征、ID和边，图级预测仍应保持不变。

**D组具体方向：用轻量TCN编码原始窗口。**

每个变量读取同一长度为30的观测窗口，使用共享的小型时序卷积网络。第一版输入为固定标准化观测、观测mask、有效相邻差分；相邻点缺失时对差分屏蔽，避免补零产生伪变化。

建议首版使用两层因果卷积，卷积核3、膨胀率1和2、输出32维时序向量。这些是控制显存与复杂度的起始设置，不是已验证的最优参数；暂不做大规模核宽或层数搜索。

```text
同一个30步窗口
  ├─ 固定标准化 → 七维统计量
  ├─ 固定标准化＋mask＋有效差分 → 共享TCN → 时序表示
  └─ 物理变量ID、所属单元ID → 身份表示
       ↓ 拼接并投影到64维
  原QC图传播与质量/一致性机制
       ↓ 原分类读出
  21类预测
```

sensor与actuator都需要时序输入，现有输入重建接口只完整保留了sensor原始窗口，必须补齐actuator路径。process_unit的时序表示可由所属变量的时序表示均值聚合，第一版继续使用固定工艺映射，不引入可学习动态图。

一致性训练中的时移负例也应由对应的移位原始窗口、mask经过同一个TCN得到，不能沿用未移位的时序表示，或把该支路直接补零。负采样策略、移位幅度和损失权重在这四组中先保持一致。

验收重点：只读取当前及过去观测；完整前向与反向无NaN；保存和加载后预测一致；统计特征与时序特征都进入分类；记录新增参数量、显存峰值和每轮耗时。

**实验控制与判定。**

首先做P2、seed=0的四组筛选。统一使用原始run划分、训练/验证窗口5,000/2,000、W=30、相同退化规则、30轮上限和早停规则。每组独立初始化训练，不从前一组的已训练权重继续微调。初筛只依据验证集；未见组合测试集留到方案确定后评测。

主要记录验证Macro-F1，同时报告Accuracy、每类召回、分类/质量/一致性损失、实际训练轮数、训练用时与峰值显存。单种子提高只能作为筛选信号；有潜力的版本补seed=1/2确认，再对最终候选完成五种子正式实验。

不预先承诺提高多少。若没有稳定增益，应根据误差分析调整或停止该项扩展；不能因为某个方案更新就默认保留。30轮预算下的筛选结论也仅适用于这一预算，不能排除更慢收敛版本在充分训练后的潜力。

使用独立输出目录，例如`results/qc_hgt_direction_20261108/P2/{A,B,C,D}/seed_0/`。目录中保存有效配置、源码提交、数据索引指纹、标准化参数和验证记录。旧代码只根据同名结果是否完成决定跳过，实施时必须补充配置校验，避免误读旧checkpoint。

初期尽量保持原batch=128。若D组在4GB显存上无法运行，先用统一较小batch对四组重跑，再做公平比较。梯度累积只保持有效梯度batch，并不会自动保持原有跨图负采样分布；需要额外处理或如实标明训练设置改变。

**时间安排与算力预算。**

代码改造、针对性检查与初次测速按半天到一天预留，这是开发估算。当前显卡为RTX 3050 Laptop、4GB显存。旧日志中稳定的每轮训练加验证约20–24分钟，30轮约10–12小时，23场景完整评估另约2.5小时；存在明显更慢的历史运行，日志墙钟时间还可能包含资源竞争或运行停顿。

| 工作规模 | 沿用旧速度的预算参考 |
| --- | --- |
| 四组、一个种子、P2，只训练与验证 | 约40–48小时 |
| 四组、一个种子、一个协议，含完整测试 | 约52–60小时，运行波动时更长 |
| 四组、五种子、P1与P2，含完整测试 | 约520–600小时；按历史实际速度外推可能接近一个月 |

以上尚未包含TCN的实测增量。第一步应以少量批次测速度和显存，随后更新预算。若原A组条件完全一致可复用，只需新增B/C/D三组，旧速度下初筛训练约30–36小时；若修改了公共执行流程、batch或随机数处理，则应重跑A组。

可先检查并优化推理时无用的负例计算、图构造缓存等开销。任何公共优化都要验证输出一致性，并处理随机数状态，不能提前承诺加速倍数。训练负采样分布的改变属于后续方法实验，不应混入首轮“纯效率优化”。

**第二阶段候选：在输入改进有效后，再增强QC机制。**

| 候选方向 | 为什么值得考虑 | 需要验证的风险 |
| --- | --- | --- |
| 消息value门控 | 单邻居softmax恒为1，现有q/c打分无法改变消息量 | 真实故障也会改变关系，门控过强可能删掉诊断信息 |
| 更可靠的质量估计 | 未受损节点占多数，执行器可靠性当前固定为1 | 要分别评估受损/未受损节点，不能把故障变化都当噪声 |
| 同图错误连接与显式跨run负采样 | 当前错误连接候选大部分来自其他图，且可能存在近重复负例 | 新辅助监督是否真正改善分类，而非只降低辅助损失 |
| 更多独立run与更长训练 | 现有5,000窗口仅覆盖约252条训练run，30轮可能不足 | 需要与所有基线共享新增预算，因素分别验证 |
| 动态图或全局注意力 | 固定局部拓扑可能遗漏跨单元联系 | 是否值得新增参数、计算量和复现成本 |

这些候选先不与B/C/D同时实施。保持P1为严格干净训练；如果新增合成退化预训练，应单列增强协议。研究窗口长度、池化替换或损失权重时也应分别进行，避免难以归因。

**正式对比方向。**

首先保留原HGT、CNN/TCN，并补Temporal-HGT，让它与新版QC-HGT使用相同的时序输入和前端。质量与一致性贡献还需用同一个QC骨干的无q/c、仅q、仅c、完整模型比较；原生HGT与当前QC层的注意力结构不同，不能单靠二者差值证明模块贡献。

外部候选优先考虑有公开代码的[GNN-TAM](https://github.com/AIRI-Institute/gnn-tam)、[TEP-ASTGCN](https://github.com/Parth-B7999/TEP-Fault-Detection-Diagnosis-GAE-ASTGCN)，资源允许时加入[GraphGPS](https://github.com/rampasek/GraphGPS)。2026年的LGF-MLTG与LSTM-GatedTAG保留为进一步核实和复现的候选，来源和已知限制见[2026-11-04文献核查记录](qc_hgt_sota_references_20261104.md)。本稿沿用该次核查，不声称重新更新了文献检索。

各模型统一21类、run划分、窗口、样本预算、调参预算和退化测试。文献原有准确率不能直接写入本项目实测表。正式报告包括五种子均值与样本标准差；按独立run进行配对分析，避免把重叠窗口当作独立样本夸大显著性。

**实施前需要保留的结果核对事项。**

现有仓库P2的QC-HGT三项Macro-F1均值为0.4292/0.4257/0.4239，与PDF表II的0.4692/0.4557/0.4539不一致。新实验应以可追溯的预测和指标为基线，另行核实PDF是否对应其他实验版本；不能用没有对应记录的数值计算提升幅度。已有[指标审计记录](qc_hgt_audit_metrics_20261104.json)可用于追溯。

审阅时最重要的三项决定是：是否采用A→B→C→D累计路线；首轮是否只做P2单种子验证；质量门控、负采样和训练预算增强是否留待第二阶段。推荐采用本稿的分阶段范围，先用最少改动识别主要收益来源。
